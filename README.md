# Party Quiz

Приложение для живого квиза на вашем ноутбуке или сервере. Один ведущий, большой экран и до 150 гостей с телефонами. Нет аккаунтов, подписок, аналитики, облачных баз, внешних шрифтов или обращений к CDN во время игры. При запуске в одной локальной сети интернет во время игры не нужен. При размещении на интернет-сервере ведущий и гости подключаются через интернет, в том числе мобильный; общая Wi-Fi сеть не требуется.

**Как разместить и запустить на сервере:** [пошаговая инструкция](DEPLOY.md). После запуска: [инструкция ведущего и гостей](USER_GUIDE.md), [версия для печати в PDF](docs/Party-Quiz-инструкция.pdf), [короткий чек-лист перед игрой](PARTY_CHECKLIST.md).

## Быстрый запуск

Требования: Node.js 24 LTS (минимум 22.12), pnpm 10.17.1, современный Chrome, Edge, Firefox или Safari. На ноутбуке для вечера рекомендуются 4 ГБ свободной памяти и свободное место для роликов и резервных копий.

```sh
corepack enable
corepack prepare pnpm@10.17.1 --activate
pnpm install
cp .env.example .env
```

Откройте `.env` и задайте **ADMIN_PASSWORD длиной минимум 12 символов**. Пустой пароль намеренно запрещает запуск. Не публикуйте `.env` и каталог `data`.

```sh
pnpm db:migrate
pnpm db:seed
pnpm build
pnpm start
```

Откройте `http://localhost:3000/admin`. Для дальнейшего запуска достаточно `pnpm start`. Express раздаёт клиент, API, Socket.IO и медиа в одном процессе. Сервер слушает `0.0.0.0`.

В подготовленной локальной копии зависимости, сборка и демонстрационный квиз уже есть. Случайный пароль записан в локальном `.env`, исключённом из Git и архива исходников.

## Возможности

- Редактор квизов с автосохранением через 650 мс после изменений, переименованием, дублированием, удалением, предпросмотром и четырьмя темами.
- Раунды и вопросы перетаскиваются за ручку/карточку. Стрелки доступны на телефонах и с клавиатуры. Карточки начала раунда, промежуточные результаты и финал формируются автоматически.
- Один или несколько правильных вариантов, текст с допустимыми альтернативами, число с погрешностью, порядок, опрос, информационная карточка, картинки, видео и «Угадай продолжение».
- Отдельные экраны `/host/:sessionId`, `/screen/:sessionId`, `/play`.
- Серверный таймер, пауза, досрочное закрытие, восстановление соединения, один ответ на вопрос, серверные очки и рейтинг.
- История сессий, удаление завершённых сессий и неиспользуемых медиа, CSV и XLSX с пятью листами.
- Демо: три раунда, 12 вопросов и информационная карточка. Включены собственный шестисекундный WebM и постер; стороннего видеоматериала нет.

## Настройка `.env`

| Переменная | Значение / назначение |
|---|---|
| `ADMIN_PASSWORD` | Обязательный пароль ведущего, минимум 12 символов |
| `PORT` | `3000` |
| `BIND_ADDRESS` | `0.0.0.0` для локального Docker; `127.0.0.1` для VPS за Caddy |
| `PUBLIC_BASE_URL` | Например `http://192.168.1.25:3000` или `https://quiz.example.com`; без завершающего `/` |
| `DATA_DIR` | `./data`, постоянное хранилище |
| `MAX_UPLOAD_MB` | `200`, лимит каждого файла |
| `MAX_PARTICIPANTS` | `200`; для обычного вечера можно задать `150` |
| `COOKIE_SECURE` | `false` для локального HTTP; `true` для HTTPS |
| `TRUST_PROXY` | `false`; `true` только за одним доверенным reverse proxy |
| `NICKNAME_BLOCKLIST` | Необязательные запрещённые фрагменты через запятую |

Сессия администратора хранится в памяти сервера 12 часов; cookie `httpOnly`, `SameSite=Strict`. После рестарта пароль потребуется снова. Участники восстанавливаются по случайному token из localStorage. Cookie/token не включаются в экспорт.

## Вечеринка в одной Wi-Fi сети

1. Подключите ноутбук к роутеру **кабелем**, а гостей — к Wi-Fi этого роутера.
2. Задайте `PUBLIC_BASE_URL` с локальным адресом ноутбука. Если он пуст, приложение выберет первый внешний IPv4 интерфейс и покажет адрес в панели. При VPN и нескольких сетях проверьте его вручную.
3. Разрешите входящие подключения к порту 3000 в системном брандмауэре. Отключите изоляцию клиентов на гостевой Wi-Fi сети.
4. Гости открывают этот адрес `/play` или сканируют QR с проектора. **Не используйте `localhost` в QR для телефонов**.
5. Проверьте вход с настоящего смартфона до приезда гостей.

Для реальной игры используйте production-сборку. В режиме разработки клиент находится на 5173, сервер на 3000; чтобы QR вёл на Vite, задайте `PUBLIC_BASE_URL=http://ВАШ_IP:5173`.

```sh
pnpm dev
```

## Docker

После заполнения `.env` создайте каталог данных и дайте контейнеру право записывать в него. На Linux официальному пользователю `node` в контейнере соответствует UID 1000:

```sh
mkdir -p data/uploads data/backups
sudo chown -R 1000:1000 data
docker compose up --build -d
docker compose logs -f
```

Контейнер запускается от пользователя `node`, автоматически применяет миграцию и создаёт демо только в пустой базе. SQLite и загрузки находятся в каталоге `./data` рядом с `docker-compose.yml`. Он не попадает в образ при пересборке; `docker compose down` и `up --build` его не удаляют. **Не удаляйте `data`**, если хотите сохранить квизы и результаты. Для VPS установите `BIND_ADDRESS=127.0.0.1` и `PUBLIC_BASE_URL=https://ВАШ_ДОМЕН`: тогда порт 3000 виден только Caddy на том же сервере, а QR ведёт на доступный гостям адрес.

В образ входят инструменты для seed-команды. Docker daemon в среде подготовки недоступен, поэтому образ здесь не запускался; обычная production-сборка Node проверена.

## Создание квиза

Нажмите «Создать квиз». Измените название, описание и тему. Добавьте раунды и вопросы. Укажите правильные варианты, таймер 5–180 секунд и очки. Для текста каждый допустимый ответ вводится с новой строки. Для порядка задайте последовательность номеров через запятую и выйдите из поля. Для чисел задайте значение и абсолютную погрешность.

Надпись «Все изменения сохранены» подтверждает запись на сервер. Пустой текст или неправильная конфигурация не сохраняются: сообщение укажет проблему. Перед закрытием редактора дождитесь сохранения; кнопки «Мои квизы» и «Начать игру» сначала завершают запись. Начатая сессия использует собственный снимок квиза, поэтому дальнейшее редактирование шаблона не влияет на гостей.

## Видео и изображения

Загрузите файл из редактора или медиатеки; существующий файл можно выбрать кнопкой рядом с загрузкой. Удаление ссылки из вопроса не удаляет сам файл. Замените ссылку, сохраните квиз, затем удалите ненужный файл в медиатеке. Файл, используемый квизом или сохранённой сессией, удалить нельзя.

Поддерживаются JPG, PNG, GIF, WebP, MP4, WebM и MOV с заголовком `ftyp`. Проверяются расширение, MIME, сигнатура и размер. Имена загруженных файлов генерирует сервер. MOV с устаревшим контейнером, начинающимся не с `ftyp`, преобразуйте в MP4. SVG и исполняемые файлы запрещены. **Расширение не гарантирует поддержку кодека**: рекомендуется MP4 H.264/AAC или WebM VP8/VP9; сервер ничего не транскодирует. Проверьте каждый ролик именно на компьютере проектора.

Видео передаётся обычным HTTP с Range Requests; через Socket.IO идут только команды. На телефоны URL видео не отправляется — используются изображение/постер и варианты. На экране ведущего ролик без звука, чтобы избежать эха.

Для «Угадай продолжение» задайте `pauseAtSeconds` раньше конца ролика. Ведущий открывает карточку и нажимает «Включить видео». Сервер открывает ответы через заданное количество секунд. Проектор останавливает ролик на этой отметке. После закрытия голосования появится статистика, затем «Показать продолжение» и «Показать ответ».

Браузер **не разрешает включить звук в другой вкладке только нажатием ведущего**. На проекторе может появиться кнопка «Разрешить воспроизведение на этом экране»: нажмите её заранее на репетиции. Если видео запустилось поздно из-за разрешения или загрузки, ведущий может поставить открытый таймер на паузу. Буферизация видео не приостанавливает серверный таймер автоматически. Оба экрана должны быть открыты до начала ролика, при сомнениях используйте обычный видео-вопрос и вручную откройте ответы.

## Проведение игры

1. Нажмите «Начать игру» на квизе — откроется лобби и будет сделана резервная копия базы.
2. «Открыть проектор» открывает отдельную вкладку. Перенесите её на проектор и включите полный экран клавишей `F`; `Esc` выключает его.
3. Гости входят по коду/QR. Ведущий видит подключённых гостей и может закрыть вход или удалить участника с подтверждением.
4. Основная кнопка и `Space` последовательно показывают начало раунда, вопрос, закрытие ответов, раскрытие и следующий вопрос. `→` выполняет основное действие. В полях ввода горячие клавиши не работают.
5. «Пауза таймера» запрещает новые ответы, сохраняя остаток времени. «Закрыть ответы» завершает приём раньше срока. «Статистика» переключает показ распределения, если он разрешён в вопросе.
6. В конце раунда основная кнопка предлагает «Итоги раунда». `L` также доступна после последнего ответа раунда. По умолчанию показывается топ-10, кнопка «Показать всех» раскрывает список. Каждый гость видит свою позицию независимо от топ-10.
7. Перед следующим раундом можно объявить перерыв. После последнего раунда появляется пьедестал и полный рейтинг.
8. Досрочное завершение подтверждается диалогом. После финала новые ответы и действия управления запрещены.

Один token может быть активен только в одной вкладке: новый вход отключает предыдущую. Для нескольких тестовых гостей используйте разные профили/инкогнито, иначе localStorage общий.

## Очки и время

Правильный ответ: `base + round(base × 0.5 × max(0, 1 − elapsed / duration))`, если включён бонус; без бонуса — `base`. Максимум 150% базовых очков, бонус линейно снижается. Паузы исключаются из elapsed. Считается время получения ответа сервером, граница дедлайна строгая; не оставляйте отправку на последние миллисекунды. Время до нуля на телефоне — только индикатор, состояние определяет сервер.

Множественный выбор — «всё или ничего»; порядок должен совпасть полностью. Текст нормализуется по регистру, пробелам, Unicode и `ё/е`. Опросы и информация не дают очков. При равенстве суммы побеждает меньшее суммарное время правильных ответов, затем стабильный ID. Очки в публичном рейтинге обновляются при раскрытии. Результат отдельного гостя доступен только ему; решения не передаются до раскрытия. Настройка «Показывать правильный ответ» скрывает решение и пояснение, но не личную оценку ответа.

## Экспорт

На финальном экране ведущего и в истории есть XLSX/CSV. Доступ защищён паролем.

- XLSX: «Итоги», «Ответы», «Вопросы», «Раунды», «События».
- CSV: подробные ответы с итоговым местом и суммой очков; если ответов нет — итоговый список участников. UTF-8 с BOM, разделитель `;` для русскоязычного Excel.

Время в журнале — ISO UTC; пользовательские строки, похожие на формулы, экранируются. Полные подробные результаты лучше скачивать после завершения.

## Сбой, восстановление и резервные копии

SQLite работает в WAL; ответ уникален по сессии, участнику и вопросу. Состояния игры и журнал записываются на диск. Перед новой игрой API резервного копирования SQLite сохраняет согласованную копию в `data/backups`. Ошибка копирования отменяет создание игры.

При перезапуске сервера открытый таймер восстанавливается **на паузе**, продолжает его ведущий. Незавершённое видео ожидает повторного запуска. Сессия, гости, принятые ответы и очки сохраняются. После краткого обрыва смартфон переподключается автоматически; обновление страницы также восстанавливает его. Не очищайте localStorage и не меняйте браузер/адрес сайта во время игры.

Перед мероприятием и после него остановите приложение, скопируйте **весь `data`**, включая `uploads`. Автоматическая SQLite-копия сама по себе не содержит видео. Восстановление: остановить приложение, сохранить текущий `data` отдельно, вернуть SQLite как `data/party.sqlite` и соответствующий `uploads`; старые `party.sqlite-wal`/`party.sqlite-shm` не переносить к восстановленной базе. Затем запустить сервер. Копии автоматически не удаляются: контролируйте свободное место.

## VPS и HTTPS

1. Направьте DNS домена на VPS и установите Docker Compose и Caddy.
2. Укажите `PUBLIC_BASE_URL=https://quiz.example.com`, сильный `ADMIN_PASSWORD`, `COOKIE_SECURE=true`, `TRUST_PROXY=true`, `BIND_ADDRESS=127.0.0.1`.
3. Запустите приложение и Caddy по примеру `Caddyfile.example`. Caddy поддерживает WebSocket через `reverse_proxy` без дополнительных правил.
4. Разрешите извне 80/443, порт 3000 оставьте доступным только Caddy. Используйте [DEPLOY.md](DEPLOY.md) для полных команд и переноса уже созданного квиза.

Для локального Wi-Fi Caddy и HTTPS не обязательны. Это приложение для частных игр: пароль ведущего не раздавайте гостям. QR содержит только адрес входа и код игры.

## Проверки и команды

```sh
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm exec playwright install chromium
pnpm test:e2e
pnpm test:load
```

Unit/integration работают с временными SQLite, реальными HTTP и Socket.IO. Playwright запускает собственный сервер на 3099 и использует `work/e2e-data`; перед ним нужна production-сборка. Для чистого повторного прогона этот тестовый каталог можно удалить при остановленном тестовом сервере.

Нагрузочный тест по умолчанию создаёт 200 реальных WebSocket-соединений и 50 вопросов, отправляя 10 000 ответов. Первый вопрос использует настоящий пятисекундный таймер и burst в последние две секунды. Для оставшихся вопросов тест переводит серверный дедлайн в последние две секунды, экономя ожидание; сами обработчики, Socket.IO и SQLite настоящие. Это тест localhost, **не измерение радиосети с 200 телефонами**. Настройки: `LOAD_CLIENTS`, `LOAD_QUESTIONS`. Отчёт: `work/load-result.json`.

Подробный статус проверки в `TEST_REPORT.md`. В данной среде самостоятельный Chromium не запускается из-за sandbox macOS; эквивалентный сценарий проверен через Playwright-локаторы встроенного браузера. Docker daemon отсутствует. Эти ограничения не следует считать успешным прогоном соответствующих команд.

## Архитектура

```text
apps/web/src         React, Tailwind, Radix Dialog, RHF, Zustand
apps/server/src      Express, авторизация, SQLite/Drizzle, Socket.IO, экспорт
packages/shared/src Zod, общие типы, события и конструкторы карточек
tests                Vitest, Playwright и Socket.IO нагрузка
assets               Собственные демонстрационные видео и постер
vendor               SheetJS 0.20.3 с лицензией в архиве пакета
data                 База, uploads, backups — не коммитить
```

FSM: `LOBBY → ROUND_INTRO → QUESTION_MEDIA/QUESTION_OPEN → QUESTION_LOCKED → ANSWER_REVEAL → … → ROUND_LEADERBOARD → … → FINISHED`; `BREAK` доступен между раундами. Переходы доступны только авторизованному ведущему и серверному таймеру. Ограничение REST рассчитано с учётом общей Wi-Fi сети; Socket.IO имеет отдельные ограничения для каждого соединения и входов с IP. Счётчики ответов объединяются в обновления раз в 120 мс; полный рейтинг не рассылается всем гостям при каждом ответе.

Одна корневая установка зависимостей упрощает этот небольшой monorepo. SQL-миграция v1 идемпотентна и выполняется при открытии базы; `db:migrate` позволяет сделать это явно. Drizzle описывает таблицы и выполняет запросы. При будущих изменениях схемы добавляйте последовательные миграции вместо изменения уже выпущенной v1.

## Wi-Fi на 150 гостей и репетиция

Нужны проверенные точки доступа на 5 ГГц, достаточная ёмкость DHCP и отсутствие client isolation. Лучше несколько проводных точек доступа с согласованной настройкой, чем один карманный роутер. Разместите их выше людей и вдали от помех. Оставьте видео только на ноутбуке/проекторе; заранее загрузите страницы, отключите сон ноутбука и автоматические обновления. Держите зарядку и резервный сетевой кабель.

Проведите репетицию на реальном оборудовании: вход 2–3 телефонов, пауза/возобновление, обновление страницы гостя, видео со звуком, QR, переход раунда, скачивание XLSX. Для полного списка откройте `PARTY_CHECKLIST.md`.

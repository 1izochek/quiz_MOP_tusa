# Party Quiz: запуск на интернет-сервере

Эта инструкция рассчитана на VPS с Linux, вашим доменом, доступом по SSH и установленными Docker Engine, Docker Compose и Caddy. Подставляйте свой домен вместо `quiz.example.com`, а своего пользователя и IP вместо `USER@SERVER`. После запуска гости смогут играть через мобильный интернет; общий Wi-Fi не потребуется. Домен должен открываться у гостей по HTTPS.

Если Docker или Caddy на сервере ещё не установлены, установите их по [инструкции Docker](https://docs.docker.com/engine/install/) и [инструкции Caddy для Linux](https://caddyserver.com/docs/install#debian-ubuntu-raspbian). Ниже описан сам Party Quiz; команды установки системного ПО зависят от вашей версии Linux.

## 1. Загрузите проект на VPS

Подключитесь к серверу и склонируйте репозиторий:

```sh
ssh USER@SERVER
git clone https://github.com/1izochek/quiz_MOP_tusa.git ~/party-quiz
cd ~/party-quiz
```

На сервере должна получиться папка `~/party-quiz` с `docker-compose.yml`, `Dockerfile` и `assets`. Репозиторий **не включает** `.env`, базу и загруженные файлы. Создайте свой `.env` на сервере.

## 2. Настройте адрес и пароль

Укажите в DNS A-записи домена IP сервера. Откройте на сервере `.env`:

```sh
cp .env.example .env
nano .env
```

Минимум для VPS:

```dotenv
ADMIN_PASSWORD=вставьте_свой_длинный_случайный_пароль
PUBLIC_BASE_URL=https://quiz.example.com
COOKIE_SECURE=true
TRUST_PROXY=true
BIND_ADDRESS=127.0.0.1
PORT=3000
```

`ADMIN_PASSWORD` должен быть длиной минимум 12 символов. Удобно сгенерировать новый командой `openssl rand -hex 24` и вставить её результат в `.env`. Храните `.env` только на сервере и в своей защищённой копии. `PUBLIC_BASE_URL` указывайте без завершающего `/`: именно он попадёт в QR-код. Не переносите в интернет старый адрес `192.168…` или `localhost`. При изменении домена участники старой игры не восстановятся с новым адресом, поэтому определитесь с доменом до вечеринки.

Приложение в контейнере должно записывать базу и видео. Создайте каталог и права:

```sh
mkdir -p data/uploads data/backups
sudo chown -R 1000:1000 data
```

Порт 3000 в этой конфигурации привязан к `127.0.0.1` сервера и не выставлен напрямую в интернет. Снаружи должны быть открыты 80 и 443 для Caddy, а также SSH для вашего администрирования. Docker предупреждает, что публикация порта без IP адреса обычно открывает его на всех интерфейсах; настройка `BIND_ADDRESS` предотвращает это на VPS. См. [документацию Docker о портах](https://docs.docker.com/reference/compose-file/services/#ports).

## 3. Запустите Party Quiz

Из `~/party-quiz` на сервере:

```sh
docker compose config --quiet
docker compose up --build -d
docker compose ps
curl http://127.0.0.1:3000/api/health
```

Последняя команда должна вернуть `{"ok":true}`. При первом запуске контейнер создаст таблицы и демонстрационный квиз. Следить за сообщениями сервера:

```sh
docker compose logs -f
```

Выйти из просмотра журнала можно клавишами Ctrl+C; сам контейнер продолжит работу. Для перезапуска после обновления кода снова используйте `docker compose up --build -d`. База и загрузки находятся в `~/party-quiz/data` и сохраняются при пересборке и перезапуске контейнера.

## 4. Подключите HTTPS

В примере ниже Caddy работает **на том же VPS**, а Party Quiz слушает только `127.0.0.1:3000`. Замените домен в `Caddyfile.example` на свой и настройте Caddy. Например, после установки Caddy как системной службы:

```sh
sudo cp Caddyfile.example /etc/caddy/Caddyfile
sudo nano /etc/caddy/Caddyfile
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
```

В файле должен быть ваш домен:

```caddyfile
quiz.example.com {
    encode gzip zstd
    reverse_proxy 127.0.0.1:3000
}
```

Caddy выпускает сертификат для домена и проксирует WebSocket соединения Socket.IO. Для автоматического HTTPS домен должен указывать на сервер, а порты 80/443 быть доступны извне. См. [Caddy: автоматический HTTPS](https://caddyserver.com/docs/automatic-https) и [reverse_proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy).

Проверьте в браузере `https://quiz.example.com/api/health`, затем откройте `https://quiz.example.com/admin` и войдите своим `ADMIN_PASSWORD`.

## 5. Проверьте игру до мероприятия

1. Создайте тестовую сессию из квиза и откройте экран проектора.
2. На телефоне **выключите Wi-Fi** и отсканируйте QR-код: он должен вести на `https://ВАШ_ДОМЕН/play?code=…`.
3. Войдите с никнеймом, запустите вопрос, отправьте ответ и дождитесь «Ответ принят!».
4. Обновите страницу телефона: никнейм и ответ должны восстановиться.
5. Покажите решение, лидерборд и скачайте XLSX.
6. Проверьте собственное видео и звук на проекторе. После репетиции запустите **новую** сессию: у неё будет новый код, а результаты теста не смешаются с основной игрой.

Подробное ведение игры описано в `USER_GUIDE.md` и печатной инструкции `docs/Party-Quiz-инструкция.pdf`.

## Сохранится ли квиз, сделанный заранее?

**Да, если вы создаёте его на уже размещённом сайте.** Название, раунды, вопросы, сессии и результаты сохраняются в `data/party.sqlite`; изображения и видео - в `data/uploads`. Выход из панели, закрытие вкладки, перезагрузка сервера, `docker compose down` или пересборка образа эти данные не стирают, пока каталог `data` остаётся на месте.

**Если квиз сделан на ноутбуке, он не появится на VPS сам по себе.** Базы у ноутбука и сервера разные. Репозиторий не включает личный каталог `data`. Для переноса выполните шаги ниже **до первой реальной игры на сервере**. Если на сервере уже есть нужные квизы, заранее решите, какую базу оставить: две SQLite-базы автоматически не объединяются. Шаги ниже сохраняют прежнюю серверную папку отдельно.

### Перенос квиза с ноутбука

1. Завершите текущую игру и остановите локальный Party Quiz (`Ctrl+C` в окне сервера). Это позволит SQLite закрыть журнал записи. Не копируйте базу во время работающей игры.
2. Скопируйте **весь каталог** `data` с ноутбука, включая `party.sqlite`, `uploads` и при желании `backups`. Не ограничивайтесь одним файлом базы: видео и картинки хранятся отдельно.
3. Остановите контейнер на VPS и отложите его текущие данные в отдельную папку:

   ```sh
   cd ~/party-quiz
   docker compose down
   mv data "data-before-import-$(date +%Y%m%d-%H%M%S)"
   mkdir -p data
   ```

4. Передайте каталог с ноутбука на сервер через SFTP-программу или `rsync`. Пример: запустите **на ноутбуке из папки проекта**:

   ```sh
   rsync -a data/ USER@SERVER:~/party-quiz/data/
   ```

5. На VPS верните права и запустите контейнер:

   ```sh
   cd ~/party-quiz
   sudo chown -R 1000:1000 data
   docker compose up -d
   ```

6. Откройте `https://ВАШ_ДОМЕН/admin`: ваш квиз должен быть в «Мои квизы». Откройте вопросы с видео и проверьте каждый файл. Обратите внимание: созданные **ранее** сессии также переедут с базой; для вечеринки лучше запустить новую.

## Резервная копия перед и после мероприятия

Приложение автоматически делает копию SQLite перед стартом каждой новой игровой сессии в `data/backups`, **но медиафайлы в такую копию не входят**. Для полной копии остановите контейнер и скопируйте всю папку `data`:

```sh
cd ~/party-quiz
docker compose down
cp -a data "data-backup-$(date +%Y%m%d-%H%M%S)"
docker compose up -d
```

Храните копию и вне VPS, иначе потеря самого сервера уничтожит и оригинал, и локальную резервную копию на нём. Не удаляйте `data`, не заменяйте рабочую базу старыми файлами во время игры и не копируйте только `party.sqlite` при запущенном приложении.

## Короткие команды на сервере

```sh
cd ~/party-quiz
docker compose ps                  # работает ли контейнер
docker compose logs --tail=100     # последние сообщения
docker compose restart             # перезапуск
docker compose down                # остановка; каталог data сохраняется
docker compose up --build -d       # обновление приложения
```

Важно: запуск на VPS и контейнерная сборка подготовлены, но в среде создания проекта Docker daemon не был доступен для проверки образа. Проверьте первые шаги на вашем сервере заранее, не в день вечеринки.
